01 / 演算法原理

Dijkstra 從起點出發，每次選出目前距離最小的有效節點，並檢查它的相鄰邊。由於邊權非負，其他尚未定案的路徑必須先經過距離至少一樣大的候選點，繼續走不會更短，因此這個節點的距離可以定案。距離可能相等；若有負權邊，就不能使用這個推論。

02 / 演算法步驟

  1. 初始化：起點 dist 為 0，其餘為 ∞；將 (0, 起點) 放入最小堆。
  2. 取出距離最小的 (dist, node)。若取出的距離與目前 dist 不同，代表條目已過期，直接跳過。
  3. 檢查每條相鄰邊：若 dist[node] + weight < dist[next]，就更新距離與 parent，並將新條目放入堆中。這稱為「鬆弛」。
  4. 重複直到佇列清空；從終點沿 parent 反向追溯，再反轉得到完整路徑。

03 / 本題路徑成本計算

路徑 0 → 1 → 3 → 5 的邊權分別為 2、4、3，因此總成本為 2 + 4 + 3 = 9。最終距離依節點 0–5 為 [0, 2, 3, 6, 5, 9]。

另一條路徑 0 → 1 → 2 → 4 → 3 → 5 的成本為 2 + 1 + 2 + 1 + 3 = 9，也同樣最短。本程式只在距離嚴格變小時更新 parent，所以保留先找到的題目指定路徑。

04 / 運算成本

設 V 為節點數、E 為無向邊數。本實作使用鄰接串列與最小堆，採 lazy deletion 時，時間複雜度為 O(V + E log(E + 1))，堆最多可保留 O(E) 個條目。對本題這類簡單圖，也常寫成 O((V + E) log V)；本題 V = 6、E = 8。

空間複雜度為 O(V + E)：鄰接串列存放節點及每條無向邊的兩個方向，dist／parent 各需 O(V)，堆最多需 O(E)。
