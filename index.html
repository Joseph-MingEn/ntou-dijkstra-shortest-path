01 / 演算法原理與正確性

Dijkstra 每次取出目前距離最小的有效節點，然後用它鬆弛相鄰邊。它的正確性依賴邊權非負：已定案節點的距離必須等於從起點出發的真正最短距離。

  1. 起點距離初始化為 0，這就是起點到自己的最短距離；其餘節點尚未找到路徑，先記為 ∞。
  2. 假設先前取出的節點都已正確定案。若本次取出的 u 還有更短替代路徑，沿那條路從起點往前看，令 y 是第一個尚未定案的節點，x 是 y 前一個已定案的節點。
  3. x 定案時已檢查 x 到 y 的邊，因此 dist[y] 至多是替代路徑走到 y 的成本。邊權非負，這個前綴成本不會大於整條替代路徑，所以 dist[y] 會小於 dist[u]；但最小堆卻先取出 u，形成矛盾。因此 u 不可能還有更短路徑，可以正確定案。
  4. 每次只在找到更小的距離時更新 dist 和 parent；parent 記下實際改善路徑的前一個節點，最後沿 parent 回溯就能還原最短路徑。負權邊會破壞上述推論，因此不能用此演算法。

距離相同時不代表更短；本程式只接受嚴格改善，保留先找到的 parent。

02 / 演算法步驟

  1. 初始化：起點 dist 為 0，其餘為 ∞；將 (0, 起點) 放入最小堆。
  2. 取出距離最小的 (dist, node)。若取出的距離與目前 dist 不同，代表條目已過期，直接跳過。
  3. 檢查每條相鄰邊：若 dist[node] + weight < dist[next]，就更新距離與 parent，並將新條目放入堆中。這稱為「鬆弛」。
  4. 重複直到佇列清空；從終點沿 parent 反向追溯，再反轉得到完整路徑。

03 / 本題路徑成本計算

路徑 0 → 1 → 3 → 5 的邊權分別為 2、4、3，因此總成本為 2 + 4 + 3 = 9。最終距離依節點 0–5 為 [0, 2, 3, 6, 5, 9]。

另一條路徑 0 → 1 → 2 → 4 → 3 → 5 的成本為 2 + 1 + 2 + 1 + 3 = 9，也同樣最短。本程式只在距離嚴格變小時更新 parent，所以保留先找到的題目指定路徑。

04 / 運算成本

設 V 為節點數、E 為無向邊數。本實作使用鄰接串列與最小堆，採 lazy deletion 時，時間複雜度為 O(V + E log(E + 1))，堆最多可保留 O(E) 個條目。對本題這類簡單圖，也常寫成 O((V + E) log V)；本題 V = 6、E = 8。

空間複雜度為 O(V + E)：鄰接串列存放節點及每條無向邊的兩個方向，dist／parent 各需 O(V)，堆最多需 O(E)。

05 / 和 BFS 比較

BFS 使用佇列，時間與空間都是 O(V + E)，適合無權圖，或每條邊權都相同的圖；它找到的是經過邊數最少的路。Dijkstra 使用最小堆，依累積權重選路，能處理不同的非負邊權，時間成本較高。

本題從 A 到 F 有兩條同為 3 條邊的路：A → B → D → F 成本是 2 + 4 + 3 = 9；A → C → E → F 成本是 5 + 2 + 6 = 13。BFS 只看見兩條路邊數相同，無法判斷成本 9 較小；Dijkstra 會比較權重並得到指定答案。

06 / 實作心得

透過逐步追蹤距離和佇列，我理解到「最少經過幾條邊」和「權重總和最低」是不同問題。較短的新路徑出現後，舊距離仍可能留在優先佇列，因此要用過期條目檢查避免重複展開；parent 則讓數值答案能還原成完整路徑。這次也讓我注意到 Dijkstra 的前提是邊權非負，選演算法時要先看清楚題目的權重條件。
